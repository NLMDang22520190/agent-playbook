## Yêu cầu
- **R1.** `ship.sh` đọc PR bằng `gh api "repos/$repo/pulls/$pr"` thay cho `gh pr view`, và suy ra cùng ba giá trị mà logic hiện có đang dùng: state (`OPEN` khi `state=open`; `MERGED` khi `merged=true`; `CLOSED` còn lại), `mstate` (`mergeable_state` chữ hoa), và oid của merge commit (`merge_commit_sha` khi đã merged). Đầu PR là `head.sha`; tên nhánh là `head.ref`. Mọi thông báo `ship refused: ...` và mã thoát của cùng một trạng thái giữ nguyên chữ.
- **R2.** Merge thường dùng `gh api -X PUT "repos/$repo/pulls/$pr/merge" -f merge_method=merge -f sha="$head"` (tương đương `--merge --match-head-commit`). Lệnh thất bại (kể cả 409 khi đầu PR đã đổi) thì `ship.sh` dừng bằng `ship refused: ...` như hiện tại. Sau khi merge thành công, nhánh được xóa bằng `gh api -X DELETE "repos/$repo/git/refs/heads/$ref"` chỉ khi repo của đầu PR bằng repo đích; xóa nhánh thất bại in cảnh báo một dòng và đi tiếp (không làm hỏng release).
- **R3.** `--auto` vẫn dùng `gh pr merge --auto` (GraphQL, không có REST). Chỉ khi có `--auto`, `ship.sh` kiểm trước, ngay đầu chạy (trước mọi thay đổi), rằng GraphQL dùng được (`gh api graphql -f query='query{viewer{login}}'` thành công). Nếu không, dừng ngay với `ship refused: --auto needs the GitHub GraphQL API, which is not reachable here; run without --auto, or from a machine with GraphQL access` và mã thoát 1.
- **R4.** Repo (`$repo`) lấy bằng `PB_GATE_REPO`, nếu không thì phân tích URL `origin` bằng đúng cách `tools/release.sh` đang dùng (`ci_repo` của slice T7); không gọi `gh repo view`. `ship.sh` giữ tự chứa (nó tự chạy lại sau `git pull`), nên đoạn lấy repo được sao vào `ship.sh`, không `source` từ file khác.
- **R5.** Không đổi: các lệnh `gh run list/view/watch` và `gh release view` (F2, F3), thứ tự bước, các hỏi đáp, log, mã thoát, ghi chú gate, `tools/release.sh`, `tools/release-gate.sh`. `mergeable_state` là `unknown` ngay sau khi push thì vẫn bị từ chối như `UNKNOWN` hiện nay (không thêm vòng thử lại).

## Ngoài phạm vi
Bỏ GraphQL cho `--auto`, vòng thử lại cho `unknown`, và việc `gh run ...` hay `gh release view` có đi qua GraphQL không (F3, chưa kiểm).

## Tiêu chí chấp nhận
Các ca dùng `gh` giả trong `tests/ship-fixture.sh` đã cập nhật để trả lời `gh api repos/R/pulls/N` và `PUT .../merge` và `DELETE .../git/refs/heads/...`, và để từ chối mọi lệnh `gh pr ...` bằng thông báo kiểu GraphQL (exit 1).
- **AC1 (R1, R2).** PR `open` với `mergeable_state: clean`: ship hỏi, gọi PUT merge với `merge_method=merge` và `sha` bằng `head.sha`, rồi DELETE nhánh, rồi tiếp tục như cũ. Log của `gh` giả không có dòng `gh pr` nào.
- **AC2 (R1).** PR `merged: true` kèm `merge_commit_sha` có trên `origin/main`: ship đi theo nhánh "already merged" như cũ.
- **AC3 (R1).** Với `mergeable_state` là `blocked`, `behind`, `dirty`, `unstable`, `draft`, `unknown` hoặc PR đã `closed` mà không merged: ship thoát 1 với thông báo `PR #N is <STATE>/<MSTATE>, needs OPEN/CLEAN (checks green, mergeable), or --auto` ghi đúng chữ hoa như hiện nay.
- **AC4 (R2).** PUT merge trả 409: ship thoát 1 với `ship refused:` nêu việc merge thất bại; không DELETE nhánh, không chạy `release.sh`.
- **AC5 (R2).** DELETE nhánh thất bại sau khi merge thành công: có đúng một dòng cảnh báo, ship vẫn đi tiếp và thoát 0 ở cuối. Đầu PR ở repo fork (repo đầu khác repo đích): không gọi DELETE.
- **AC6 (R3).** `--auto` với GraphQL giả lỗi: thoát 1 trước `git switch`, `git fetch` hay bất kỳ lệnh `gh api` ghi nào, với đúng câu của R3. `--auto` với GraphQL giả ổn: gọi `gh pr merge --auto ... --match-head-commit <head>` như cũ.
- **AC7 (R3).** Không có `--auto`: không gọi `gh api graphql`.
- **AC8 (R4).** Với `PB_GATE_REPO=o/r`, mọi đường dẫn REST là `repos/o/r/...`; không đặt biến và `origin` là một đường dẫn có đuôi `github.com/o2/r2.git`: `repos/o2/r2/...`. Không có lệnh `gh repo view`.
- **AC9 (R5).** Toàn bộ các ca đã có trong `tests/test-ship*.sh` (với fixture cập nhật) còn đúng các assertion về thứ tự bước, log, hỏi đáp và mã thoát; không assertion nào bị bỏ hay làm yếu, chỉ đổi cách giả lập lệnh gọi `gh` (pr view thành api).
- **AC10.** `git diff` của slice không chứa `tools/release.sh`, `tools/release-gate.sh`, `tools/ci-tree-tested.sh`, `.github/`.

## Rủi ro
- Đây là đường merge thật: một sai sót làm merge nhầm hoặc không chặn được merge khi đầu PR đã đổi. Giảm bằng `sha=` trong PUT (F5, [CHƯA KIỂM CHỨNG] cho đến khi chủ repo thử ở local) và AC4.
- Hành vi thật của REST (F4, F5) chưa gọi được ở đây; test chỉ chứng minh `ship.sh` gọi đúng đường dẫn và đối số, không chứng minh GitHub trả đúng. Cần một lần chạy thật của chủ repo (ví dụ `ship.sh` với PR dùng thử) trước khi tin; tôi không chạy `ship.sh` thật.
- `mergeable_state` REST được GitHub tính lười: có thể `unknown` ngay sau khi push, khác tần suất của GraphQL [CHƯA KIỂM CHỨNG]. Hậu quả: ship từ chối một PR đang tốt, người chạy chạy lại.
