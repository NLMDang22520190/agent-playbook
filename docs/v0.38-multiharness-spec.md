# 02 - Spec: multi-harness (Claude + Codex), .NET, zero footprint, smaller core, scope against built-ins

Status: draft, queued for v0.38 (`docs/scorecard.md`). Written 2026-11-20 against installed playbook 0.37.0. Companion of
`docs/v0.37-learnings-spec.md` (01). It was written in a session that did not have this repo: tests, CHANGELOG and eval
locations were unknown then. Nothing in it is implemented.

Labels: [VERIFIED] read or run this session; [INFERRED] reasoned from named facts; [UNVERIFIED] not checked.

## Source
- User chat 2026-11-19/20: (a) the playbook must work in Codex as well as Claude; (b) four friction points:
  .NET test paths, no footprint in the repo, SKILL.md context cost, checkpoint commits polluting history;
  (c) "the goal of the playbook is a skill set that can be applied to the company's workflow"; remove what Claude and
  Codex already do well (code review, verify, goal...).
- Nothing below is a requirement the sources did not suggest. Open choices are listed with defaults.

## Goal
A small core that does what the harnesses do not (role separation enforced by git, evidence tied to the working tree,
approved lessons), installs once per machine for both harnesses, leaves no trace in a company repo unless the team
opts in, and delegates review, verification, planning and sandboxing to built-in commands.

**Weight:** W1, W2, W4: Lite (config, docs, reversible). W3, W5, W6: Full (change script paths and the shape of the skill).

## Scope against built-ins (the main decision)
Test per component: does a built-in do the same job at equal or better quality, in both harnesses? Quality of the built-ins
was **not measured here**; the table is a proposal from their documented behaviour. Check one real task with and without each
item before removing (W6).

| Component | Overlaps with | Proposal | Reason / what stays |
|---|---|---|---|
| `roles/reviewer.md` checks 4 (correctness), 5 (scope and slop), 6 (security) | `/code-review`, `/security-review`, Codex `/review` | **Remove from the role; call the built-in** | Keep checks 1 (AC coverage), 2 (mutation), 3 (test quality), 7 (evidence re-run): no built-in does them (F9). The reviewer prompt tells the agent to run the built-in review first and attach its findings. |
| Reviewer "If the change touches UI" section, the always-on rule "user-visible change needs one real observation" | `/verify` (Claude); Codex has no named equivalent in the pages read | **Shorten to one rule: use `/verify` where it exists, else run the app and report; else "Not checked"** | Keeps the evidence requirement, drops the procedure text. |
| Phase 1 spec text: Understanding, scan log, other readings | `/plan` (plan mode), Codex `/plan` | **Keep the AC table with source anchors; drop the rest to a short template** | Plan mode proposes a plan; it does not copy ACs verbatim with anchors or list a regression corpus. |
